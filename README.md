# Mamaearth Returns & Growth Intelligence Pipeline

DAAIG Capstone — Data Analytics with AI & GenAI
Masai School × E&ICT Academy, IIT Roorkee

A three-layer analytics pipeline over Mamaearth order data. A SQL relational
store reports what the raw data says, a pandas layer cleans it and quantifies
what is actually true, and a GenAI narrator turns those verified numbers into a
business narrative.

**The rule the whole repository is built on:** no layer reports a number it did
not itself compute or receive from the layer before it.

```
sql/                  analysis/                narrator/
raw truth        →    cleaned truth       →    the narrative
₹99,860.20            ₹97,358.30               "COD returns 44.4%…"
180 orders            175 orders               findings.json
```

Parts 1 and 2 both read the raw CSVs and never each other. That independence is
deliberate: it is what makes the ₹2,501.90 gap between the two totals provable
rather than assumed.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
python3 -m pip install pandas matplotlib google-genai
```

Requires Python 3.9+ and SQLite 3.

`google-genai` is the current client (`from google import genai`), not the older
`google-generativeai` package. It is needed only for the online narrator path —
step 3 runs without it.

## Running the pipeline

Run everything from the repository root. Parts 1 and 2 are independent and can
be run in either order; Part 3 needs Part 2 to have produced `findings.json`.

### 1 · SQL relational layer

```bash
rm -f mamaearth.db
sqlite3 mamaearth.db < sql/schema.sql
sqlite3 mamaearth.db < sql/seed_data.sql
sqlite3 -header -column mamaearth.db < sql/reports.sql
```

After loading you should have 45 customers, 16 products and 180 orders.

`seed_data.sql` uses SQLite's `.import`, which loads blank CSV cells as empty
strings rather than NULL. The loader repairs this immediately afterwards, so
`discount_pct` and `rating` hold real NULLs. Confirm with:

```sql
SELECT DISTINCT typeof(rating) FROM orders;   -- integer, null
```

Without that repair, `COUNT(rating)` returns 180 instead of 165 and report (b)
is silently wrong.

### 2 · Cleaning and analysis

```bash
python3 analysis/clean_and_eda.py
```

Reads the raw CSVs, standardises payment casing, removes five duplicate orders,
imputes missing values, merges, computes order values, flags quantity outliers,
tests two hypotheses, corrects the monthly series, and writes
`narrator/findings.json`.

Every intermediate result is printed — the acceptance figures are in the output,
not buried in the code.

### 3 · Visualisations

```bash
python3 analysis/visualize.py
```

Regenerates both PNGs from the raw CSVs. The revenue chart uses the
outlier-corrected series.

### 4 · The narrative

With a free Gemini key from [Google AI Studio](https://aistudio.google.com):

```bash
export GEMINI_API_KEY="your-key-here"
python3 narrator/generate_narrative.py
```

With **no key at all** — deterministic, offline, no network:

```bash
unset GEMINI_API_KEY
python3 narrator/generate_narrative.py
```

Both paths produce the same three SCR sections and the same five key figures,
and both write `narrator/sample_output.txt`. The offline path runs on a bare
Python install: no API key, no network, and no third-party packages.

**Never commit the API key.** It is read from the environment. A local `.env` is
loaded if `python-dotenv` happens to be installed, but it is optional and
`.env` is git-ignored.

## Findings

| | |
|---|---|
| Raw revenue | **₹99,860.20** across 180 orders |
| Cleaned revenue | **₹97,358.30** across 175 orders |
| Reconciliation | **₹2,501.90** — exactly the five duplicate orders removed |
| Payment split | CARD 70 · UPI 55 · COD 55 |
| COD return rate | **44.4%**, against 18.9% UPI and 14.7% Card |
| Highest-risk segment | **COD in Tier-2 cities, 54.5%** (Tier-1 is 37.5%) |
| True peak month | **March 2026, ₹20,318.90** |
| Customer with no orders | C045, Vihaan |

### The three results worth reading twice

**The gap is fully explained.** ₹99,860.20 − ₹97,358.30 = ₹2,501.90, which is
exactly the combined value of the five duplicate orders (O0176–O0180) removed in
cleaning. The delta is computed independently by summing those five rows, not by
subtracting one total from the other — so the explanation is tested rather than
assumed. Imputing missing discounts and ratings changes revenue by zero.

**A blended rate hides the driver.** COD returns at 44.4% overall, but that is
not uniform: Tier-1 cities run at 37.5% and Tier-2 at 54.5%. Acting on the
blended figure would spread effort evenly across cities that do not share the
risk evenly.

**January's lead is an artifact.** On the raw series January leads at
₹29,582.10. Two bulk orders land there — O0011 (25 units, 28 Jan) and O0098
(30 units, 10 Jan). Excluding them drops January to ₹11,637.10 and **March
becomes the genuine peak at ₹20,318.90**. Outliers are flagged, not deleted:
they are real orders and belong in the revenue total.

### Hypotheses tested

| Hypothesis | Verdict |
|---|---|
| COD orders are returned more often than prepaid | **Confirmed** — 44.4% vs 14.7% Card |
| Higher discounts reduce returns | **Busted** — r = −0.09, negligible |

All six correlation pairs across rating, returned, discount and quantity fall in
the negligible band (|r| < 0.2).

## Notes on the implementation

**Cleaning order is deliberate.** Standardise casing → drop duplicates → impute
→ merge → flag outliers. The rating median must come from the deduplicated frame
or five ratings vote twice; outliers must be flagged before the monthly series
or the January artifact is never found.

**Duplicates are matched on a natural key.** Every row has a unique `order_id`
by design, so a plain `drop_duplicates()` finds nothing. The match uses the eight
columns that describe the order itself, with `order_id` deliberately excluded.

**`findings.json` is generated, never typed.** It is written at the end of
`clean_and_eda.py`, which is what stops the narrative from quoting a number the
analysis did not produce.

**Nothing third-party is imported at module scope in the narrator.** The offline
path has to run with zero environment configuration, so `google-genai` and
`python-dotenv` are both imported lazily, inside functions, after the checks that
decide whether they are needed at all.
